========================================================================
                      MAGENTARTOS MPU ARCHITECTURE REPORT
                   Target: RP2350 (Cortex-M33 / ARMv8-M)
                   Design: The "Isolated Windows" (v2.0)
========================================================================

1. FILOSOFIA DI SICUREZZA "ISOLATED WINDOWS"
-------------------------------------------
Il sistema opera con una netta separazione dei privilegi:
- KERNEL (SUDO): Opera in Background Region (PRIVDEFENA=1). Ha accesso 
  illimitato a tutta la memoria RAM (TCB, code, variabili globali).
- TASK (USER): Opera in modalità Unprivileged (User Mode). Vive in un 
  "buio totale" (Default No-Access) eccetto per le finestre (Regioni MPU) 
  esplicitamente aperte dal Kernel.

2. MAPPA DELLE REGIONI MPU (Rigorosamente NON sovrapposte)
---------------------------------------------------------
Sull'architettura ARMv8-M (Cortex-M33), la sovrapposizione delle regioni 
causa un MemManage Fault immediato. La mappa attuale è:

| ID | Nome Window | Base Address | Limit Address | User Acc. | XN (Exec) |
|---|---|---|---|---|---|
| 0 | FLASH_SEC   | 0x10000000   | 0x11FFFFFF    | RO        | ALLOW     |
| 1 | SIO_GPIO    | 0xD0000000   | 0xD000FFFF    | RW        | FORBID    |
| 2 | PERIPHERAL  | 0x40010000   | 0x4003FFFF    | RW        | FORBID    |
| 3 | FLASH_NS    | 0x00000000   | 0x01FFFFFF    | RO        | ALLOW     |
| 4 | TASK_STACK  | Dinamico     | Dinamico      | RW        | FORBID    |

Dettagli Tecnici:
- Region 0/3: Coprono gli alias Secure/Non-Secure della Flash (Cached e Uncached).
- Region 2: Limitata chirurgicamente a IO_BANK0 e UART0 per impedire ai task 
  di manipolare Timer, DMA o altri controller hardware critici.
- Region 4: Riconfigurata ad ogni Context Switch (isr_pendsv).

3. PROTEZIONE STACK CON PSPLIM
------------------------------
Il Cortex-M33 offre un registro hardware dedicato allo Stack Overflow:
- PSPLIM: Viene aggiornato ad ogni context switch con l'indirizzo `stack_base`.
- Se il puntatore allo stack (PSP) scende sotto questo limite, l'hardware 
  blocca l'operazione PRIMA della corruzione dati, scatenando un fault.

4. ARCHITETTURA SYSTEM CALL (SVC)
---------------------------------
Per richiedere servizi al Kernel (es. I/O, Delay), i task utilizzano le 
Supervisor Calls (SVC). Questo permette il passaggio sicuro da User Mode 
a Privileged Mode.

Meccanismo di Dispatching:
- Assembly (isr_svcall): Recupera lo Stack Pointer (PSP/MSP). 
- Inversione Registri: Passa R0=ID e R1=Pointer_Args al dispatcher C.
- Dispatcher C (OS_Syscall_Handler): Esegue l'azione con privilegi elevati.
- SafePrintf: Il Kernel gestisce la formattazione delle stringhe per proteggere 
  le variabili globali della libreria C dall'accesso Unprivileged.

5. GESTIONE DEI PRIVILEGI E IDLE TASK
-------------------------------------
- Modalità PRIVILEGED: Riservata al Kernel e all'IDLE TASK. 
  L'Idle Task deve essere privilegiato per poter eseguire l'istruzione `WFI` 
  (Wait For Interrupt) senza causare crash di protezione.
- Modalità UNPRIVILEGED: Tutti i task utente corrono in questa modalità. 
  Tentativi di disabilitare gli interrupt (CPSID/CPSIE) o modificare la MPU 
  vengono bloccati dall'hardware.

6. DIAGNOSTICA FAULT (LED ROSSO)
--------------------------------
In caso di violazione della sicurezza, il Kernel entra in "Panic Mode":
- MemManage Fault: 1 Lampeggio LUNGO e LENTO. (Accesso memoria non autorizzato).
- HardFault: 3 Lampeggi VELOCI. (Errore hardware o corruzione grave).
Durante il fault, il sistema viene congelato per prevenire escalation di danni.
